# AI vs Open Source

We at unyt.org believe in the power of open source and the importance of community-driven development.
The whole idea of open source is based on the concept of people sharing their work and collaborating to create software that benefits everyone, not just a few big coorporations.

This is not to say that big companies and Open Source are enemies per se - many big companies contribute to open source or provide tools and services like GitHub, which is also where unyt.org sourc code is currently hosted.

But with the advancements in LLMs (a.k.a. "AI"), the whole concept of open source and community-driven development is being more and more threatened by those big coorporations.

It is easy for an LLM to "create" some software by just replicating existing open source code, on which it was either directly trained on or which it can easily find online, without giving any credit to the original authors or contributors.
This is a huge problem, not only because it at least unethical and potentially illegal when it comes to copyright and licensing, but also because it is so easy to create lots and lots of low-quality slop code, which nobody feels responsible for anymore.

A recent example that demonstrates this problem is the case of [Chardet](https://github.com/chardet/chardet/issues/331), a popular Python library for character encoding detection, which was completely rewritten using LLM agents and then released by the current maintainers under a new license without giving any credit to the original authors or contributors.
This sets a very dangerous precedent and is a clear example of how LLMs can be used to undermine the principles of open source and community-driven development.

Besides from obvious rewrites, there's also demo projects like the C compiler that was recently published by Anthropic, claiming that it was fully generated by an LLM.
While this can definitely be seen as an impressive achievement, it is still very questionable whether it is really a good thing to push existing, high-quality human-created code into an LLM to then have it generate a new version of the same code just because it can be done.

While LLMs are definitely fascinating and can be a useful tool in the right hands, they are not a replacement for the creativity, innovation, and collaboration of the open source community.

Especially for junior developers, it is important to learn how to write code themselves and to understand the principles of software development, rather than just relying on LLMs to generate code for them. Since we have lots of contributers and interns that are just starting out with programming, we want to make sure that they have the opportunity to learn and grow as developers, rather than just being able to copy and paste code from an LLM without really understanding it.

Also for more experienced developers, it is important to maintain the quality of our codebases by ensuring that all contributions are human-created and someone takes responsibility for them.

This is why we at unyt.org want to keep our software human-created by enforcing an anti-AI policy for all of our projects.
We are not anti-AI in general, any use of AI tools that can assist developers to solve problems or do research is definitely welcome, but we strongly oppose the usage of fully automated, agent-generated code in all of our projects.

We know that it is not really possible to determine with 100% certainty whether a piece of code was generated by an LLM or not, but we will reserve the right decline any contributions that we have reason to believe were generated by an LLM, as well as to remove any code from our repositories that we have reason to believe was generated by an LLM.
